# 速查卡：30 分钟拿 80%

按「一句话 + 关键数字」组织。展开看对应分册，动手细节回原文。

## 全局（00 总纲）

- RAG 瓶颈常在**检索**不在生成：垃圾进，垃圾出。
- 两条腿互补：关键词管"一字不差"（错误码/型号/法条），向量管"意思相近"。
- 万能三角：**召回率 × 延迟 × 资源**，所有调参都是边上滑动。
- 跨系统老朋友：WAL（translog/log broker）、不可变+标记删除+后台合并（merge/compaction）、局部 top N+全局归并、批量摊销、有损换资源、最终一致+补偿、幂等是重试前提。

## ES 实战（01 分册）

- LIKE 两个死穴：前导通配符全表扫；匹配是布尔值给不出相关性 → 倒排索引（词典+posting list+打分原料）。
- 倒排的代价：写入放大、空间>原文、秒级可见 → 主数据留 MySQL。
- **法则：字段怎么进的索引就怎么查**——term 查原值（keyword/数字/日期），match 先分词（text）。
- bool：must=AND算分，filter=AND不算分（位图缓存），must_not=NOT，should=加分。
- 分词：standard 对中文逐字切（UAX #29）；**索引 ik_max_word + 搜索 ik_smart**（反了=事故）；调试用 `_analyze` 两端对照。
- BM25 = TF（饱和）×IDF（稀有词值钱）×长度折扣；默认 k1=1.2、b=0.75。
- 排序诡异 → `explain: true`；业务加权 boost（2~5 起）→ function_score（置顶 replace）。
- 聚合：指标（avg/stats/cardinality=HLL 近似）+ 桶（terms/range/date_histogram，可嵌套）；query+aggs 一次请求，`size:0`。
- terms 的 doc_count 是**近似**（分片各自聚合只报本地 topN）；`shard_size=size×1.5+10`；对账别用。
- Java：用 `elasticsearch-java`（RestHighLevelClient 已废弃）；client 全局单例；**bulk 按 5~15MB、部分成功必须逐 item 检查**。

## Milvus 实战（02 分册）

- 语义鸿沟：字面不匹配、语义匹配；同义词词典是枚举，问法是组合。
- embedding=高维向量，意思近方向近，余弦度量；归一化后 COSINE/L2/IP 排序等价，默认 COSINE，**metric 跟着 model card 走**。
- 向量无全序 → 没有 B+ 树 → ANN 拿召回换速度；向量在精确词上失明（10053≈10054）。
- **主键用业务主键**（doc_id+序号）；Milvus 不拦重复主键；**dim 建后不可改，换模型=全量重灌**。
- 模型选型顺序：语言→维度(内存)→长度上限→部署→榜单只初筛；`normalize_embeddings=True`；bge 查询侧加指令前缀。
- 索引三角：**FLAT**（精确基准）/ **IVF_FLAT**（构建快，nlist 建时 `4√N`、nprobe 查时调）/ **HNSW**（RAG 默认，M/efConstruction 建时、ef 查时≥top-k）/ **DiskANN**（向量下盘，必须 SSD）。
- ef/nprobe = 花延迟买召回：**自己量**（FLAT 出 ground truth → 扫参 → 找拐点），别抄博客。
- 过滤：filter 进引擎=bitset 等价 pre-filter；**应用层过滤是错误方案**；HNSW 被滤点保留作路径。
- 租户/环境必带互斥条件 → partition key（2.3+）；灵活条件 → filter。
- 客户端：MilvusClient / MilvusClientV2；单例 Bean；**upsert 要求主键归业务管**（会修订的知识库别用 auto_id）；删除是逻辑标记等 compaction；一致性默认 Bounded（联调 Strong）。

## 运行机制（03 分册）

- FST = 共享前缀+后缀+稀疏索引（只索引 block 入口）；vs B+ 树：允许 miss；ES 不自管缓存 → JVM 堆别大。
- posting list：delta 编码 + FOR 位打包（128/组）；交并 roaring bitmap。
- doc values：聚合排序要"文档→字段值"，倒排方向答不了 → 列存一份。
- ES 写入：buffer → **refresh 1s**（进 page cache 即可查不 fsync）→ merge → **flush 30min/512MB** 清 translog。可见性=page cache，持久性=fsync。
- translog vs redo：逻辑 vs 物理；ES 把 segment 生成+落盘全挪出关键路径（translog 接持久性）。
- segment 不可变：删除=.del 位图、更新=新写+旧删、merge 回收（LSM 家族）。
- 查询：query then fetch；深分页每分片排 `from+size`，`max_result_window=10000`，正路 `search_after`。
- 分布式打分：统计量分片本地 → 分数不可比；别过度分片；**DFS=多一轮 RTT 换全局统计**（分数被严肃使用时才开）。
- 集群：master 管户口不碰数据（类比 Kafka controller）；路由 `hash%主分片数` 不可改；副本同步复制站写入关键路径；in-sync 集合踢慢副本；脑裂靠**多数派**（7.0 自动）；凑不够多数派=拒服是设计。
- 红色排查：health 定位索引 → `_cat/shards` 找 UNASSIGNED → `_cluster/allocation/explain` → 磁盘水位 85/90/95、节点不够、分片上限 1000/节点、恢复中。
- IVF：k-means 分桶，损失在边界点，数据分布变要重建。
- HNSW vs 跳表：高层稀疏底层稠密形似；**神异——跳表索引有序链表有数学保证，HNSW 索引近邻图靠图质量**；删除是硬伤（tombstone）。
- PQ：切 96 段×256 质心=32 倍压缩伤召回（补救：粗筛+原向量重排）；SQ：float32→int8 几乎无损。
- Milvus 五角色：proxy / coordinator×4 / 三 worker / 对象存储（真相）/ log broker。
- **log broker vs Kafka：消息即数据本身**，不是通知；消费者挂了换实例重订阅。
- growing（订阅日志即可查）→ seal（512MB）→ sealed（不可变落对象存储）。
- 一致性四档=GuaranteeTs 怎么定：Strong 追平 / **Bounded 落后一窗（默认）** / Session 自己写的可见 / Eventually。RAG：批量导入 Bounded/Eventually，上传即问 Session。
- 检索旅程：proxy 广播扇出（向量查询无分片键）→ segment 局部检索（sealed 走索引、growing 暴力扫）→ bitset 下推 → 多路归并。**距离全局可比 → 无 ES 打分坑、无需二次回表**。
- 慢查询两嫌疑人：参数给猛了 / segment 碎片化；**P99 跟写入吞吐同形状 = growing 积压**。

## RAG 实战（04 分册）

- 切分决定天花板：**语义完整且单一**；递归切分默认起点；chunk_size 256~512 token 是起点不是结论。
- overlap=给切不准买的保险：硬切多留 10~20%，按结构切 0~5%。
- 元数据四件：doc_id（溯源+增量更新）、title_path（免费语义锚点）、chunk_index（邻居扩展）、权限标签。
- BM25 三修正：k1 词频饱和 1.2 / b 长度归一 0.75 / IDF 平滑不翻负。分数依赖全库统计量=相对量。
- **RRF：只用排名 1/(k+rank)，k=60**，要"两路都说好"；归一化合并有坑（刻度漂移+离群值）。
- 单 ES 还是 +Milvus：百万向量内+已有 ES → 单 ES；千万+/要量化下盘/检索独立重负载 → Milvus。
- 双塔（零交互、可预计算）管召回；cross-encoder（交互足、不可预计算）管精排。
- 漏斗：召回 top10~20 → RRF 合并 20 → rerank 出 3~5。
- rerank 救不了烂召回：先查正确答案在不在 top 20——不在=召回的病（chunk/模型/权重），在但靠后=rerank 的主场。
- 指标：RAG 优先 **recall@k**（漏召回不可修复→LLM 硬编；排序粗糙可修复）；MRR 其次。
- 评测集：真实 query 最值钱（LLM 生成要改口语化）；标准="单独能否直接回答"；50~200 条起步，badcase 回流。
- RAGAS：忠实度（抓幻觉）、答案相关性（反向生成问题）；LLM 裁判离线抽样跑，换裁判=换尺子。
- 增量更新：先删后插（**upsert 删不掉变少的旧 chunk → 残留理直气壮答错**）；先删后插天然幂等=双写补偿基石。
- 双写：检索比交易宽容（旧文档≠资损）→ 最终一致+重试+对账，**别上分布式事务**。
- 降级：熔断一路单路撑；**两边全挂必须报错**，绝不让 LLM 裸答。
- 监控：延迟分段 / **空结果率单独打点**（常规监控里永远"成功"）/ 评测集周跑基线。
