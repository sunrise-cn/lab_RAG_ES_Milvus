# 16 量化压缩实测【进阶】：省多少内存、掉多少召回

## 这个实验验证什么

[专栏三·05](../专栏三-运行机制/05-ANN索引原理.md)第四节给过两个结论：SQ 温和（每维独立映射到 int8，约 4 倍压缩，几乎不掉召回），PQ 猛（切子段加码本，压缩几十倍，召回受伤）。这一篇把两个结论拿到自己手里量：同一份数据建三种索引——FLAT、IVF_SQ8、IVF_PQ——去 MinIO 控制台亲眼看索引文件大小差几倍，再拿 FLAT 当标准答案实测 SQ8 和 PQ 的 recall@10。省内存和掉召回是同一枚硬币的两面，这次你把两面都翻过来看。

它也是实验 12 的续集。12 量的是三角的"用延迟换召回"那条边，这次量"用召回换内存"那条边。做完这题，三角的三条边就都有你自己的数字了。

进阶实验，完全隔离：只用主环境 Milvus，collection 全部 `exp16-` 前缀，做完清理，跳过它不影响实验 17。

关联正文：[专栏三·05](../专栏三-运行机制/05-ANN索引原理.md)（IVF/HNSW/PQ/SQ 的原理与取舍）。

## 实验材料构建

两个脚本，分工如下：

| 脚本 | 干什么 |
|------|--------|
| [exp16-gen.py](lab/scripts/exp16-gen.py) | 造 10 万条带簇结构的向量，灌进三个 collection（exp16-flat / exp16-sq8 / exp16-pq），各建索引 |
| [exp16-run.py](lab/scripts/exp16-run.py) | 实测三个索引的 recall@10 和平均延迟，顺带打出 collection_id（去 MinIO 对目录用） |

三件事先说清。

其一，数据和实验 12 是**同一份**：生成逻辑逐行相同、种子同为 1212。这样实验 12 里 IVF_FLAT 的测量结果可以直接拿来当"无量化的 IVF"基线（下一步解释怎么用）。你跳过了实验 12 也不影响本实验，只是少一个对照。

其二，2.4 里量化不是独立的索引类型，是挂在 IVF 家族上的变体——`IVF_SQ8`、`IVF_PQ`。所以这里量的是"IVF+量化"对比 FLAT，recall 里天然混着两部分损失：IVF 桶裁剪的 + 量化失真的。怎么把量化那部分剥出来，现象解释里做。

其三，PQ 的参数：m=16 是把 128 维切成 16 段、每段 8 维（m 必须整除 dim）；nbits=8 是每段 256 个质心。参数名的准确写法以 pymilvus 2.4.4 实际为准——待验证。

```python
# lab/scripts/exp16-gen.py
"""实验 16 材料：三个 collection 灌同一份带簇结构的向量，建三种索引。

exp16-flat: FLAT（暴力，ground truth 尺子）
exp16-sq8 : IVF_SQ8（nlist=100）
exp16-pq  : IVF_PQ（nlist=100, m=16, nbits=8）

数据和实验 12 是同一份（种子 1212、100 簇 x 1000 条、sigma 0.35），
所以实验 12 里 IVF_FLAT 的测量可以直接拿来当"无量化基线"。

注意：2.4 里量化不是独立索引类型，是 IVF 家族的变体（IVF_SQ8 / IVF_PQ）。

运行方式（先激活 venv）：
  cd lab && source .venv/Scripts/activate
  python scripts/exp16-gen.py
"""
import time
from pathlib import Path

import numpy as np
from pymilvus import (
    Collection,
    CollectionSchema,
    DataType,
    FieldSchema,
    connections,
    utility,
)

LAB = Path(__file__).resolve().parent.parent
DATA = LAB / "data"

DIM = 128
N_CLUSTERS = 100
PER_CLUSTER = 1000          # 100 簇 x 1000 条 = 10 万条
N_QUERIES = 100
NOISE = 0.35
BATCH = 5000

INDEXES = {
    "exp16-flat": {"index_type": "FLAT", "metric_type": "L2", "params": {}},
    "exp16-sq8": {"index_type": "IVF_SQ8", "metric_type": "L2",
                  "params": {"nlist": 100}},
    # IVF_PQ 参数名（m/nbits）以 pymilvus 2.4.4 实际为准——待验证
    "exp16-pq": {"index_type": "IVF_PQ", "metric_type": "L2",
                 "params": {"nlist": 100, "m": 16, "nbits": 8}},
}


def main():
    DATA.mkdir(exist_ok=True)
    connections.connect(host="localhost", port="19530")

    # ---- 以下生成逻辑与 exp12-gen.py 逐行相同（含种子），产出同一份数据 ----
    rng = np.random.default_rng(1212)
    centers = rng.uniform(-1.0, 1.0, size=(N_CLUSTERS, DIM))
    noise = rng.normal(0.0, NOISE, size=(N_CLUSTERS * PER_CLUSTER, DIM))
    vectors = np.repeat(centers, PER_CLUSTER, axis=0) + noise
    ids = np.arange(N_CLUSTERS * PER_CLUSTER, dtype=np.int64)
    q_center = rng.integers(0, N_CLUSTERS, size=N_QUERIES)
    queries = centers[q_center] + rng.normal(0.0, NOISE, size=(N_QUERIES, DIM))

    for name, index_params in INDEXES.items():
        if utility.has_collection(name):
            utility.drop_collection(name)
        schema = CollectionSchema([
            FieldSchema("id", DataType.INT64, is_primary=True),
            FieldSchema("vector", DataType.FLOAT_VECTOR, dim=DIM),
        ])
        col = Collection(name, schema)
        t0 = time.perf_counter()
        for i in range(0, len(ids), BATCH):
            col.insert([ids[i:i + BATCH].tolist(),
                        vectors[i:i + BATCH].tolist()])
            print(f"  {name} insert {min(i + BATCH, len(ids))}/{len(ids)}")
        col.flush()
        col.create_index(field_name="vector", index_params=index_params)
        col.load()
        print(f"{name}: {col.num_entities} 行，{index_params['index_type']} 索引，"
              f"已 load（灌数据+建索引 {time.perf_counter() - t0:.0f}s）")

    np.savez(DATA / "exp16.npz", queries=queries)
    print(f"query 已存 {DATA / 'exp16.npz'}")
    print("材料就绪。下一步：python scripts/exp16-run.py")


if __name__ == "__main__":
    main()
```

```python
# lab/scripts/exp16-run.py
"""实验 16 主测量：三种索引的 recall@10 + 平均延迟 + collection_id。

FLAT 是 ground truth 尺子，SQ8/PQ 的 recall 拿它对答案。
collection_id 打出来是给 MinIO 那一步用的：去 index_log 目录里对号。

运行方式（先激活 venv）：
  cd lab && source .venv/Scripts/activate
  python scripts/exp16-run.py
"""
import time
from pathlib import Path

import numpy as np
from pymilvus import Collection, connections

LAB = Path(__file__).resolve().parent.parent
DATA = LAB / "data"

TOPK = 10
WARMUP = 3

# nprobe=16 对齐实验 12 的 IVF_FLAT 扫描档：桶裁剪条件一致，recall 的差值才是纯量化失真
PLANS = [
    ("exp16-flat", "FLAT", {"metric_type": "L2", "params": {}}),
    ("exp16-sq8", "IVF_SQ8", {"metric_type": "L2", "params": {"nprobe": 16}}),
    ("exp16-pq", "IVF_PQ", {"metric_type": "L2", "params": {"nprobe": 16}}),
]


def run_batch(col, queries, search_params):
    for q in queries[:WARMUP]:
        col.search(data=[q.tolist()], anns_field="vector",
                   param=search_params, limit=TOPK)
    t0 = time.perf_counter()
    results = [col.search(data=[q.tolist()], anns_field="vector",
                          param=search_params, limit=TOPK) for q in queries]
    total = time.perf_counter() - t0
    return total / len(queries) * 1000, [list(hits.ids) for hits in results]


def recall(id_lists, truth):
    hit = sum(len(set(a) & set(b)) for a, b in zip(id_lists, truth))
    return hit / (len(truth) * TOPK)


def collection_id(col):
    """能拿到就拿（去 MinIO 对目录），拿不到不影响测量。"""
    try:
        return col.describe().get("collection_id", "未知")
    except Exception:
        return "未知（以实际为准）"


def main():
    connections.connect(host="localhost", port="19530")
    queries = np.load(DATA / "exp16.npz")["queries"]

    truth = None
    for name, index_type, search_params in PLANS:
        col = Collection(name)
        avg, id_lists = run_batch(col, queries, search_params)
        if truth is None:
            truth = id_lists
            r = 1.0                      # FLAT 拿自己对自己，定义就是 1
        else:
            r = recall(id_lists, truth)
        print(f"{name:<12} {index_type:<8} recall@10={r:.4f}  "
              f"avg={avg:.2f}ms  collection_id={collection_id(col)}")


if __name__ == "__main__":
    main()
```

## 现象解释

**文件大小那三行数字，机制各算一遍。** FLAT 索引就是原始向量本身：10 万条 × 128 维 × 4 字节 = 51.2MB，这就是那 1x。IVF_SQ8 是 SQ 量化后的向量：每个维度独立做线性映射，float32 压成 int8，一条向量 512 字节变成 128 字节，正好 1/4——量化发生在"每一维各自"的层面，信息只丢在映射的舍入里。IVF_PQ 更进一步：128 维切成 16 段、每段 8 维，每段单独跑一个小 k-means 训出 256 个质心，一条向量只存 16 个"每段最近质心的编号"——16 字节，对 512 字节是 32 倍压缩，再加码本和桶结构的固定开销，就是你看到的 ~1/25。压缩的暴力程度，决定了接下来 recall 掉的深度。

**recall 那三行，把两种损失剥开看。** 三份 recall 里混着两种来源不同的损失：IVF 桶裁剪的（SQ8 和 PQ 都有），加量化失真的（各自不同）。剥法用实验 12 的数字：同一份数据、同样的 nprobe=16，实验 12 里 IVF_FLAT（无量化、纯桶裁剪）的 recall@10 是 0.9767。把它摆进序列：

```text
FLAT       1.0000
IVF_FLAT   0.9767   （实验 12 的数字）—— 桶裁剪损失 2.3 个百分点
IVF_SQ8    0.9613   —— SQ8 量化失真再吃掉 ~1.5 个百分点
IVF_PQ     0.8937   —— PQ 量化失真再吃掉 ~8 个百分点
```

桶裁剪的部分三家一样（都是 nprobe=16 扫 100 个桶），差值就是纯量化失真：SQ8 约 1.5 个百分点，PQ 约 8 个百分点。这和正文那句"SQ 温和、几乎不伤召回；PQ 猛、召回受伤"对上了，而且你手里有了自己的数。

为什么 PQ 伤得重？SQ 的失真是"每维各丢一点舍入误差"，128 个误差加起来还是小量。PQ 的失真是结构性的：8 维挤在 256 个质心里，两个本来有细微差别的向量落到同一段的同一个质心上，这段的距离贡献直接算成零——差异不是变小了，是被抹掉了一角。而最近邻竞争恰恰发生在千分之几的距离差上，抹掉的就是排名。

**延迟那列值得多看一眼：量化不但没慢，反而更快了。** SQ8 的距离计算从 float 变 int8，PQ 干脆把乘加变成查表求和（16 次查表加 16 次加法对一条候选）。所以量化是三角里唯一"同时改善两条边"的操作：内存降一个量级、延迟还低——代价全部记在 recall 头上。省内存和掉召回，同一枚硬币的两面，这句话现在有了三行数据。

## 常见坑点

**只看文件大小不看 recall，就敢上线 PQ。** 25 倍的压缩很诱人，8 个百分点的 recall 损失藏在第二步的输出里。文件大小是收益，recall 是价格，两个数必须一起看——这是实验 12 立下的规矩，换一条边一样成立。

**m 不整除 dim 直接建。** PQ 的 m=16 要求 128 % 16 == 0，每段才是整数 8 维；m=17 会建索引失败。nbits=8 对应每段 256 个质心（2^8），改成 4 就是 16 个质心，压缩更狠、失真更大，是进一步实验的题目。

**以为量化索引建索引不要钱。** IVF 家族要跑 k-means 训桶心，PQ 还要训 16 个码本——gen 脚本输出里 PQ 那行"灌数据+建索引"最慢不是错觉。数据分布大变后，经验做法是重建索引，这笔钱还要再付一次。

**在 insert_log 里找量化、找不到，以为量化没生效。** 量化长在 index_log 的索引文件里，insert_log 是原始数据，本来就不变。判断量化生效看 index 文件大小和 load 后内存，不看 insert_log。

**recall 分母又记错。** 和实验 12 同一口径：ground truth（FLAT 的 top-10）命中数除以 (query 数 × 10)，不是"返回结果里相关的比例"。

## 进一步实验

把 exp16-run.py 里 SQ8 和 PQ 的 nprobe 从 16 改成 100（= nlist，桶全扫）再跑：桶裁剪损失被买回来，SQ8 的 recall 会冲到 0.99 以上，PQ 却卡在 0.9 附近上不去——nprobe 救得了桶裁剪，救不了量化失真，因为后者不是"漏扫"，是"编码本身就近似了"。这一步把两种损失的性质彻底分开。

或者把 gen 脚本里 PQ 的 nbits 从 8 改 4（每段 16 个质心），重跑 gen 和 run：索引文件再小一半，recall 再掉一截。SQ8 也值得对照——SQ 没有类似 nbits 的旋钮，它的压缩比是定死的 1/4，这本身就是两种量化的一个性格差异。

有兴致的话补一手 rerank：PQ 先搜 top=100，拿 npz 里存着的原始向量对这 100 条精算 L2、重排取 top-10，看 recall 能从 0.89 捞回多少（正文给的路数：粗筛快、精排准）。代价是 top-100 的原始向量距离计算和"原始向量得留在能取到的地方"这笔工程账。

## 最后，总结

量化是三角的第三条边：用召回换内存。SQ8 拿 1/4 的内存换约 1.5 个百分点的召回，温和到可以当默认选项；PQ 拿几十倍的压缩换约 8 个百分点，是内存成为硬约束时的狠招。索引文件的大小在 MinIO 里眼见为实，recall 的价签要用 FLAT 当尺子自己量，而 recall 里混着的桶裁剪损失和量化失真来源不同、救法不同——nprobe 买得回前者，买不回后者。至此，召回-延迟-内存三角的三条边，你都量过了。
