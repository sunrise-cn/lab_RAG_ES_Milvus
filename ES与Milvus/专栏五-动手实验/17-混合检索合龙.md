# 17 混合检索合龙：BM25、向量与手写的 RRF

## 这个实验验证什么

ES 的 `_score` 和 Milvus 的 distance 是两把刻度不同的尺子，不能直接比大小——这个结论[专栏四·02](../专栏四-RAG实战/02-BM25算法与混合检索.md)论证过，这次亲手撞一次。50 条小语料，一半带错误码/型号/编号（BM25 的主场，向量的盲区），一半用标准术语写、口语提问对不上字面（向量的主场，BM25 的盲区）。同一个查询发两路，各自 top-5，然后手写 RRF 合并——只用排名，不用分数——再跑一个"归一化后分数直接相加"的对照组，看它错在哪。

这是专栏五的收官实验：从实验 01 的第一条 curl 到这里，ES 和 Milvus 两条线第一次在同一个查询里合龙。

关联正文：[专栏四·02](../专栏四-RAG实战/02-BM25算法与混合检索.md)（BM25 打分、量纲问题、min-max 的坑、RRF 与 k=60）。

## 实验材料构建

两个脚本，分工如下：

| 脚本 | 干什么 |
|------|--------|
| [exp17-seed.py](lab/scripts/exp17-seed.py) | 50 条语料同时灌进 ES（索引 exp17-docs）和 Milvus（collection exp17-docs，embedding 用多语言小模型） |
| [exp17-search.py](lab/scripts/exp17-search.py) | 4 个测试查询，双路检索 + 手写 RRF + 分数相加对照组 |

语料怎么设计是本实验的关键，两类各 25 条：

- **err-xx 精确词类**：IT 工单句，带错误码、型号、编号。错误码对 embedding 模型是一串没有语义的噪声 token，但 BM25 靠它一击命中。
- **col-xx 口语同义类**：文档全部用标准术语写——"系统启动耗时过长"这种书面话。用户问的是"电脑开机特别慢"，字面上一个字都对不上，BM25 全瞎；但意思向量知道。

ES 侧 text 用默认 standard 分词器（IK 装没装都不影响本实验）。Milvus 侧用 `paraphrase-multilingual-MiniLM-L12-v2`——多语言小模型，中文够用、CPU 上快。它的输出维度以你实际下载的模型为准，所以 seed 脚本先 encode 一条测试句把维度量出来再建 schema，从机制上保证"schema 维度 = 模型维度"，不给手抄维度留出错机会。

def main():

    es = Elasticsearch("http://localhost:9200")

    print(f"加载 embedding 模型 {MODEL_NAME}（首次运行会先下载）...")
    model = SentenceTransformer(MODEL_NAME)
    dim = int(model.encode("维度测试").shape[0])
    print(f"模型输出维度 dim={dim}（以实际为准，schema 按它建）")

    # ---- ES 侧 ----
    if es.indices.exists(index=ES_INDEX):
        es.indices.delete(index=ES_INDEX)
    es.indices.create(index=ES_INDEX, mappings={"properties": {
        "doc_id": {"type": "keyword"},
        "text": {"type": "text"},        # 默认 standard 分词器
        "kind": {"type": "keyword"},
    }})
    for doc_id, text in DOCS:
        es.index(index=ES_INDEX, id=doc_id,
                 document={"doc_id": doc_id, "text": text,
                           "kind": doc_id.split("-")[0]})
    es.indices.refresh(index=ES_INDEX)
    print(f"ES 索引 {ES_INDEX} 灌入 {es.count(index=ES_INDEX)['count']} 条")

        FieldSchema("text", DataType.VARCHAR, max_length=512),
        FieldSchema("vector", DataType.FLOAT_VECTOR, dim=dim),
    ])
    col = Collection(MILVUS_COLLECTION, schema)
    texts = [t for _, t in DOCS]
    vectors = model.encode(texts, normalize_embeddings=True)
    col.insert([[d for d, _ in DOCS], texts, vectors.tolist()])
    col.flush()
    col.create_index(field_name="vector", index_params={
        "index_type": "FLAT", "metric_type": "COSINE", "params": {}})
    col.load()
    print(f"Milvus collection {MILVUS_COLLECTION} 灌入 {col.num_entities} 条"
          f"（FLAT/COSINE，已 load）")
    print("材料就绪。下一步：python scripts/exp17-search.py")

主测量脚本：

```python
# lab/scripts/exp17-search.py
"""实验 17 主测量：双路检索 + 手写 RRF + 分数相加对照组。

对每个查询做四件事：
  1. ES BM25 检索 top-5
  2. Milvus 向量检索 top-5（COSINE，distance 越小越相似）
  3. RRF 合并：score = Σ 1/(k + rank)，k=60，只用排名不用分数
  4. 对照组：两路分数各自 min-max 归一化后直接相加

运行方式（先激活 venv）：
  cd lab && source .venv/Scripts/activate
  python scripts/exp17-search.py
"""
from elasticsearch import Elasticsearch
from pymilvus import Collection, connections
from sentence_transformers import SentenceTransformer

ES_INDEX = "exp17-docs"
MILVUS_COLLECTION = "exp17-docs"
MODEL_NAME = "paraphrase-multilingual-MiniLM-L12-v2"
TOPK = 5
RRF_K = 60   # RRF 惯用值：第 1 名 1/61、第 2 名 1/62，压低单路头部的垄断性

QUERIES = [
    "报错 ERR-1002 连接超时怎么处理",   # 偏精确词：错误码是 BM25 的独门武器
    "RTX-4090 显卡驱动老是崩溃",        # 偏精确词：型号靠精确匹配
    "电脑开机特别慢要好几分钟",          # 偏口语：和标准术语文档几乎零字面重叠
    "网太卡了视频一直转圈",              # 偏口语：共享"视频/网"等字，两路都能沾边
]


def tag(doc_id):
    return "精确词" if doc_id.startswith("err-") else "口语类"


def brief(text):
    return text if len(text) <= 18 else text[:18] + "…"


def es_search(es, query):
    resp = es.search(index=ES_INDEX, query={"match": {"text": query}}, size=TOPK)
    return [(h["_id"], h["_score"], h["_source"]["text"])
            for h in resp["hits"]["hits"]]


def mv_search(col, model, query):
    emb = model.encode([query], normalize_embeddings=True)[0]
    hits = col.search(data=[emb.tolist()], anns_field="vector",
                      param={"metric_type": "COSINE", "params": {}},
                      limit=TOPK, output_fields=["text"])[0]
    return [(str(h.id), float(h.distance), h.entity.get("text")) for h in hits]


def rrf_fuse(*routes):
    """routes: 每路一个 [(doc_id, score, text)]，只用排名：Σ 1/(k + rank)。"""
    scores = {}
    for route in routes:
        for rank, item in enumerate(route, start=1):
            doc_id = item[0]
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (RRF_K + rank)
    return sorted(scores.items(), key=lambda kv: (-kv[1], kv[0]))


def minmax_norm(pairs):
    """[(doc_id, score)]（score 越大越好）→ {doc_id: 归一化分数}。"""
    if not pairs:
        return {}
    vals = [s for _, s in pairs]
    lo, hi = min(vals), max(vals)
    if hi == lo:
        return {d: 0.5 for d, _ in pairs}
    return {d: (s - lo) / (hi - lo) for d, s in pairs}


def sum_fuse(es_route, mv_route):
    """对照组：min-max 归一化后直接相加。缺某一路记 0。"""
    es_norm = minmax_norm([(d, s) for d, s, _ in es_route])
    # distance 越小越好，取负变成"越大越好"再归一化
    mv_norm = minmax_norm([(d, -s) for d, s, _ in mv_route])
    scores = {}
    for doc_id in set(es_norm) | set(mv_norm):
        scores[doc_id] = es_norm.get(doc_id, 0.0) + mv_norm.get(doc_id, 0.0)
    return sorted(scores.items(), key=lambda kv: (-kv[1], kv[0]))


def show(title, items):
    print(f"[{title}]")
    for rank, item in enumerate(items, start=1):
        if len(item) == 2:                       # 融合结果 (doc_id, score)
            doc_id, score = item
            print(f"  {rank}. {doc_id}({tag(doc_id)})  {score:.4f}")
        else:                                    # 单路结果 (doc_id, score, text)
            doc_id, score, text = item
            print(f"  {rank}. {doc_id}({tag(doc_id)})  {score:.3f}  {brief(text)}")


def main():
    connections.connect(host="localhost", port="19530")
    es = Elasticsearch("http://localhost:9200")
    model = SentenceTransformer(MODEL_NAME)
    col = Collection(MILVUS_COLLECTION)

    for query in QUERIES:
        print(f"\n================ {query} ================")
        es_route = es_search(es, query)
        mv_route = mv_search(col, model, query)
        show("BM25 路", es_route)
        show("向量路", mv_route)
        show(f"RRF 合并（k={RRF_K}）", rrf_fuse(es_route, mv_route))
        show("对照组：归一化相加", sum_fuse(es_route, mv_route))


if __name__ == "__main__":
    main()
```

## 实验步骤

**1. 先用 _analyze 验一下分词**

错误码能不能被 BM25 命中，取决于 standard 分词器把它切成了什么。验一下（这是 [_analyze](01-第一次见ES-REST-API全景.md) 的老用法）：

```bash
curl -s -X POST "http://localhost:9200/exp17-docs/_analyze" -H "Content-Type: application/json" -d '{"field": "text", "text": "报错 ERR-1002 连接超时怎么处理"}'
```

预期你会看到（示意，节选）：`ERR-1002` 被拆成 `err` 和 `1002` 两个 token，中文被拆成单字 `报`、`错`、`连`、`接`……两件事各记一笔：错误码没被整串吞掉，拆出来的 `1002` 照样能精确匹配，BM25 有抓手；中文按单字切分，字面重叠的计算就是这么粗糙。

**2. 跑四路对照**

```bash
python scripts/exp17-search.py
```

先看 Q1（错误码查询），预期你会看到（示意；分数具体多少不重要，各行的相对关系才是）：

```text
================ 报错 ERR-1002 连接超时怎么处理 ================
[BM25 路]
  1. err-01(精确词)  8.1  报错 ERR-1002 连接超时，检查网关防火…
  2. err-13(精确词)  1.0  Git push 报 ERR_CONNECTION_RESET，代理…
  （后面都是只蒙到 err 一词的弱匹配，分数断崖）
[向量路]
  1. err-01(精确词)  0.29  报错 ERR-1002 连接超时，检查网关防火…
  2. err-06(精确词)  0.31  HTTP 502 Bad Gateway，上游服务连接被网关…
  3. err-05(精确词)  0.34  Oracle 报 ORA-12170，客户端到监听器的会话…
[RRF 合并（k=60）]
  1. err-01  0.0328     2. err-06  0.0323     3. err-05  0.0161
[对照组：归一化相加]
  1. err-01  2.000      2. err-06  0.91       3. err-13  0.06
```

三件事值得看：BM25 的第一名是断崖式的（8.1 对 1.0），错误码 `1002` 这个独占 token 的杀伤力；向量路也把 err-01 排到第一，但分数是渐变的（0.29 对 0.31）——"连接超时"是有语义的，错误码对 embedding 的干扰没大到找不回来（错误码越生僻、语义词越少，向量路越容易把它排到后面，实测为准）；err-01 两路第一，RRF 双份 1/61 拿下榜首。对照组在这条查询上恰好没错——记下这点，Q3 再看它翻车。

## 现象解释

**对照组错在哪，分两层。** 第一层是最原始的错：直接拿 `_score + distance` 相加。BM25 的分数是 8 分制的相对量，COSINE distance 挤在 0~1 里、差值只有小数点后两位——加起来，向量路连小数点都排不上，等于没投过票，整个榜单被 BM25 的量纲支配。这就是"两把刻度不同的尺子不能直接比"的工程版本。

第二层是 min-max 归一化修不掉的病。尺度是修平了（都拉到 0~1），但 min-max 的刻度尺是**本次召回集的最好最差成绩**（正文三节的原话）：BM25 第一名无论是 8.1 分的强匹配还是 2.1 分的弱蒙合，归一化后都是 1.0——分数里"这次到底可信不可信"的信息被抹平了；BM25 的分数形状是断崖（第一名 8.1、第二名 1.0，归一化后 1.0 对 0.05），向量的形状是缓坡（均匀铺在 0~1），相加的结果由断崖那一支配：BM25 第二名往后全部被压扁，一路实际上只剩"第一名"一票。对照 Q1 的对照组输出——err-13 拿 0.06，err-06 靠向量的 0.9 分反超——两路信息的权重比例，就这样被两家的分布形状私下定了，你没法控制。

**RRF 为什么稳。** 它整个计算里没有出现过任何一路的原始分数：`1/(60+rank)`。排名是跨路可比的——"BM25 榜第 2"和"向量榜第 2"都是货真价实的信息；分数不可比的问题被整体绕开。k=60 的含义也在你的输出里现形：第 1 名 1/61、第 2 名 1/62，差不到 2%——RRF 有意压低"单路第一名"的权威，要的是**两路都说好**的文档（Q1 的 err-01 两路第一、双份 1/61，谁也压不住它）。代价也看得见：一路全瞎时（Q3），另一路的第一名也只剩 1/61 这一点微弱优势——k 越小（比如 k=1）单路第一越权威、k 越大越平均主义，60 是社区试出来的温和值。

**两路的盲区是结构性的。** 错误码、型号这类 token，对 BM25 是高 IDF 的宝贝，对 embedding 模型是切碎后毫无语义的噪声；口语和术语的字面错位，对 BM25 是零重叠的死局，对向量是同义近邻的近路。混合检索不是两路保险冗余，是两路互补——合龙榜单的价值就在 Q1 和 Q3 这种"一路盲区"的查询上。

## 常见坑点

**直接拿 `_score + distance` 相加。** 量纲、方向（一个越大越好一个越小越好）、分布形状三重不对齐，上面已经拆完。哪怕归一化救回量纲，形状支配还在。

**embedding 模型和检索模型不是同一个。** 库里 50 条是 A 模型算的，查询用 B 模型算——两个向量空间没有任何对应关系，COSINE 算出来全是噪声（[专栏二·03](../专栏二-Milvus实战/03-Collection与Schema.md)讲过：换模型等于全量重灌）。本实验 seed 和 search 用同一个模型常量，就是为了不犯这个错。

**错误码被 standard 分词器整串吞掉。** `_analyze` 就是干这个的（步骤 1 已经验过）。`ERR-1002` 切成 `err`+`1002` 还能检索；要是你的错误码长成了分词器不切开的形状，或者被切得比这碎得多，BM25 的精确匹配就废了——上 BM25 前先 `_analyze`，别信直觉。

**RRF 榜上并列就怀疑代码写错了。** k=60 下相邻名次只差 2%，两路第一名互换第二的文档分数恰好相等（Q4 可能给你表演这个）。并列是 RRF 的常态，不是 bug。

**只拿一两个查询下结论。** 4 个查询是示意级的玩具规模，真实语料上两路榜单长、重叠稀疏，行为会平顺很多。评测集要覆盖"精确词为主、口语为主、两路都行"三类查询，各看各的盲区——这正是正文说的"按评测调权重"。

## 进一步实验

把 `rrf_fuse` 改成加权版（`w_bm25/(k+rank) + w_vec/(k+rank)`），BM25 权重从 1 扫到 3：Q1 里 err-01 的领先越拉越大，Q3 里向量路第一名对零命中的 BM25 的优势也越明显——"精确词重要就加重 BM25，口语化提问多就加重向量"，正文这句方针你可以扫出自己的数。

或者把 RRF_K 从 60 改成 1 再改成 600：k=1 时第 1 名 1/2、第 2 名 1/3，单路头部垄断，Q1 的 err-01 一骑绝尘，但 Q4 里两路互换名次的文档差距也被放大——k 是"多信单路第一名"的旋钮，扫一圈你对 60 这个默认值的合理性会有体感。

## 最后，总结

BM25 和向量是两路互补的检索：错误码/型号是 BM25 的独门武器，口语同义是向量的主场，各自的盲区都是结构性的。两路的分数不可比——量纲、方向、分布形状三重不对齐，归一化救得回尺度救不回形状；RRF 只用排名，1/(k+rank) 加和，k=60 压低单路权威、奖励两路共识，一路全瞎时自然退化成另一路。到这里，专栏五收口：实验 01 你发出的第一条 `_cat` curl，到这一步，同一个查询里 ES 和 Milvus 各自给出榜单、你亲手把两条线拧成了一份——BM25 管"字面必须精确"，向量管"意思相近"，融合只信排名。接下来该把这份榜单塞给大模型了，那是专栏四后半段的故事。
