# 专栏五：动手实验，把机制摸出温度

前四个专栏是"看懂"，这个专栏是"摸过"。读一百遍"segment 不可变"，不如亲手删一万条数据，再看一眼磁盘占用纹丝不动。

## 设计原则

每个实验都遵守五条：

1. **先手感，后机制**。前三个热身实验先建立"功能地图"和"手感"——API 都摸一遍、图形界面连上看看、磁盘上亲眼看一眼数据长什么样；核心概念的实验放在这之后，不一上来就扎机制。
2. **一个实验只验证一个核心概念**。概念清单来自专栏一~四的正文，每个实验开头标了它对应哪几篇。
3. **每个实验自带材料构建**。不依赖任何其他实验留下的数据和状态，从"实验材料构建"小节照抄命令，就能从干净状态完整复现；每一步都写"预期你会看到什么"。
4. **进阶实验完全隔离**。标了【进阶】的实验（10、11、16）随时可做、随时可跳过，不影响主线；它们不用主实验留下的任何状态（10 甚至用独立的三节点集群，独立端口）。
5. **坑点单列**。做完实验要对常见陷阱有肌肉记忆，而不只是"跑通了"。

环境一次搭好：所有实验共用一套 Docker 环境（版本钉死，含 Kibana 和 attu 图形界面），搞砸了 `docker compose down -v` 重置重来。环境怎么搭见 [00-实验环境](00-实验环境.md)。

## 各实验的关键观察点

- **04**：GET 立刻可见、search 搜不到 → 1 秒后才可见；`refresh_interval=-1` 后永远搜不到，手动 refresh 才行
- **05**：中文被 standard 拆成单字后 `term "苹果"` 查不到；ik_max_word 与 ik_smart 的切分差异；索引分词与搜索分词不一致的经典坑
- **06**：首条数据定类型终身——字符串日期被动态映射成 date 后脏数据写不进；数字先入变成 float 后字符串写不进；类型错了只能 reindex
- **07**：删一半数据磁盘占用不变（`docs.deleted` 计数），force merge 后才物理回收；update 的真相是新写一条+旧条打标记
- **08**：用 `_explain` 拆分看——词频 5 次分高但不到 5 倍（k1 饱和）；同样一次关键词，短文压长文（b 归一）
- **09**：`from=10000` 直接 400；30 万条数据下 1 分片 vs 5 分片的放大对比；PIT + search_after 正确遍历全量
- **10**【进阶】：kill master 看重新选举；停两个节点看少数派行为；单节点上副本无处安放 → yellow（"两节点集群是假高可用"）
- **11**【进阶】：30 万条数据，bulk 批大小（200/1000/5000/20000）× refresh_interval（1s / -1）的吞吐矩阵——最差组合和最优组合能差出一个数量级；代价是关掉 refresh 期间数据不可搜
- **12**：10 万条带聚类结构的 128 维向量，FLAT 出 ground truth，HNSW 调 ef、IVF 调 nprobe，自己画出 recall-QPS 曲线
- **13**：手造 2 维向量心算验证——IP 偏好同向长向量、L2 偏好最近点；归一化后 L2 与 COSINE 排序完全一致
- **14**：insert 后立刻 search——Strong 保证全见，Bounded/Eventually 能见到几条取决于时机（这正是"一致性级别 = 等待水位"的直观体现）
- **15**：极低命中率的 filter 导致 top-k 返回不满（"先 top-k 后过滤"的坑）；partition key 裁剪前后多轮取均值的延迟对比
- **16**【进阶】：同一份向量数据建 FLAT / SQ8 / PQ 三种索引——去 MinIO 控制台亲眼看索引文件大小差几倍，再实测各自的 recall@10，"省内存掉多少召回"拿到自己的数字
- **17**：50 条小语料（一半含错误码/型号精确词、一半口语化同义），双路检索 + 手写 RRF，对比"分数直接相加"的反例

## 实验文档的固定结构

每篇实验都是同样的七段：

1. **这个实验验证什么**——核心概念一句话 + 对应正文篇目
2. **实验材料构建**——照抄可复现的命令和脚本（脚本真实文件在 `lab/scripts/`）
3. **实验步骤**——编号步骤，每步带"预期你会看到"的输出示意
4. **现象解释**——把看到的东西落到机制层，和正文对上
5. **常见坑点**——实践里真正翻车的地方
6. **进一步实验**——选做延伸，改一个变量再看一次
7. **最后，总结**

一个诚实声明：文档里的"预期输出"是按机制推理写出的**示意**，不是在环境里逐条跑出来的实录（环境在你机器上，得你来跑）。如果实际输出和示意对不上，先别怀疑自己——记下差异，回头去啃现象解释，那往往是实验最有价值的时刻。

## 怎么用

先把 [00-实验环境](00-实验环境.md)搭好（一次），然后每个实验四拍：照抄材料构建 → 按步骤走、对照预期输出 → 读现象解释 → 跑坑点和进一步实验。搞砸就 `down -v` 重来。

做实验的正确姿势不是"验证文档说得对"，而是**预测**：每一步执行前，先猜自己会看到什么，再按回车。猜对了说明机制懂了；猜错了更值钱——你找到了自己理解里的 bug。
